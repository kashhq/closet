# Styles, fonts and the service worker source

- **CSS**: Tailwind v4 (`@tailwindcss/cli`) + daisyUI. Source `views/assets/main.css`, compiled to `public/bundle.css` by `npm run generate:tailwind`. **Theme (R1, #81; the owner chose "Atelier", 2026-09-27):** two daisyUI themes in `main.css`, `closet-light` (default) and `closet-dark` (follows `prefers-color-scheme`, no toggle), daisyUI's built-ins off; flat (no shadows), 1px borders, the plan's radii; `base-200` is the one neutral plinth behind cutouts; `accent` is the clay. `src/web/theme-colors.ts` holds base-100 as hex for the manifest and the two `<meta name="theme-color">` tags (a unit spec fails if it drifts from main.css's oklch). **Fonts:** Inter (UI) and Fraunces (headings), `@fontsource-variable`, Latin subset, weight axis only, `font-display: swap`; `npm run generate:fonts` (inside `generate:vendor`) copies content-hashed woff2 into `public/vendor/fonts/` and writes the generated, git-ignored `fonts.css` that `main.css` imports, so **the fonts step must run before Tailwind**: `generate:tailwind` and `generate:tailwind:watch` run `generate:vendor` first themselves (#119), so no caller has to remember it; the service worker precaches `woff2`.

**Touch sizing (#636):** where the pointer is coarse, `main.css` raises `--size-field` (44 px controls), keeps text fields at 16 px or more (iOS zoom) and gives dense controls (btn-sm/-xs, tabs, checkbox/radio/toggle, `.link`, control badges) a transparent 44 px `::after` (`::before` on an input `.btn`/`.tab`); never size a control for touch at its call site (`min-h-11`). A control whose own overflow clips (`truncate`) loses the area: truncate an inner span. Two areas that overlap count against each other, so a row of small controls needs room between them for the areas (#1210). **How a target is measured** (`tapMisses`, `test/support/tap-area.ts`; the page audit and `expectTouchTargets` in `test/trips.spec.ts`): a 44 px disc hit tested by the browser, so a pseudo-element's area counts (axe's own `target-size` is 24 px and never sees it) and a disc a pixel short passes (43 px does, 42 px fails; pinned in `scripts/audit/a11y.browser.spec.ts`, run by `make ci-e2e`); never loosen it to pass, space the controls.

`src-sw.ts` is the service worker: its doc is `src/web/shell/AGENTS.md` (PWA and the service worker). `outbox.ts` is the page's offline outbox and `page/*.ts` the other client modules, each bundled into `public/js/gen/<name>.js` (`npm run generate:pages`) and type-checked by `tsconfig.page.json` (with `page-globals.d.ts` and `page-vendor.d.ts`): how they are built and share names with the views is `src/web/shell/AGENTS.md`, Client modules; the outbox's own doc is `src/web/shell/outbox.md`. `outbox-store.ts` is the outbox database's one definition, imported by both bundles.

- **daisyUI's `daisyui.*` layers rank above `components`** in the bundle, so a rule that overrides a daisyUI component (the inactive section-tab colour, #726) goes in `@layer utilities`, not components and not unlayered.

- **Cards (#727): `Card` in `src/web/card.tsx`, two variants, never a hand-composed `card ...`** (`cardClass(variant, extra)` when the element is a `PostForm`, a `label` or a button). `content` is a hairline `border border-base-300` on `base-100`: what a page shows (Today's rows, Profile's sections, Muse's cards) and anything a cutout sits on, since `base-200` is the plinth. `inset` is a `base-200` fill for an inset form panel (the repair form, a brand-size row, the sign-in frame); never put a cutout straight on it, the garment would lose its plinth. `bodyClass` adds the `card-body` and its padding. **No shadows**: ESLint refuses `shadow-*` in any class string that does not also name `dropdown-content`, an `alert` (a toast) or a sheet's dialog box (daisyUI's modal box class).
