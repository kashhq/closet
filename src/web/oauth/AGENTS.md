# OAuth for /mcp

_Reference, not auto-loaded:_ [`reference.md`](reference.md) holds the consent in full: the authorize request's proof order, the page, the signed field and the POST's budgets.

`src/web/oauth/` (#681; design `docs/plans/2026-11-27-mcp-oauth.md`, sections 4.1 to 4.9): hosted MCP clients (the Claude app's custom connectors, ChatGPT's) connect to `/mcp` with OAuth 2.1, per the MCP authorization spec (revision 2026-07-28). Built: discovery (#1289), the consent page and its one-time codes (#1290), the token endpoint (#1291). Agent Access's listing is #1292.

- **On exactly when `MCP_PUBLIC_URL` is set** (`loadConfig`; `WebConfig.oauth`, built once by `oauthDiscovery`, `discovery.ts`). It is `https://<public MCP host>/mcp`: the resource (RFC 8707/9728) and, by its origin, the issuer. The boot refuses a non-https URL, a path other than `/mcp` or with a query, fragment or credentials, a host that is not `SITE_URL`'s or an `ALLOWED_HOSTS` entry, and a non-https `SITE_URL`. The boot logs `OAuth discovery on: ...` or `OAuth off: ...` (logger `OAuth`).
- **Nothing an agent calls needs the tailnet** (owner, 2026-11-27): `/mcp`, `/oauth/token` and the discovery documents are served on the public MCP host; only `authorization_endpoint` (`SITE_URL/oauth/authorize`, the consent sheet in the person's browser) is on the tailnet. RFC 8414 allows the authorization endpoint on another host than the issuer.
- **The documents** (`routes.ts`, on the `oauth` surface, `public`): Protected Resource Metadata (RFC 9728) at `/.well-known/oauth-protected-resource/mcp` and the bare `/.well-known/oauth-protected-resource` (MCP's fallback; the same document); Authorization Server Metadata (RFC 8414) at `/.well-known/oauth-authorization-server`: `code` only, `authorization_code` and `refresh_token`, S256 only, `none` (public clients), `client_id_metadata_document_supported`, `authorization_response_iss_parameter_supported` (RFC 9207), no `registration_endpoint` (no DCR) and no `offline_access`. `public, max-age=3600`; no statement; one `OAUTH_DISCOVERY_LIMIT` budget per address across them.
- **Off, every name is a JSON 404** (`NotServed`, guards.conf `@not-served`), and `/.well-known/openid-configuration` always is: the exact routes win over the shell's `/.well-known/*` `{}` catch-all, which a discovering client would read as broken metadata.
- **The `/mcp` 401 points here when on**: `WWW-Authenticate: Bearer realm="closet", resource_metadata="<issuer>/.well-known/oauth-protected-resource/mcp", scope="closet:read closet:write"` (`mcpChallenge`, carried by the bearer gate's `HttpError` as `challenge`; the root error handler writes it). A hosted client reads it only on a 401.
- **The `oauth` surface** (`src/web/surface.ts`): no cookie (the root preValidation hook skips it), errors are RFC 6749 section 5.2 JSON (`{ error, error_description }`, `sendOAuthError`, `errors.tsx`) from the error handler and the same-origin hook, a POST with no Origin passes and a foreign one is a 403. `assignSurface` refuses it off `/.well-known/oauth-*`, `/.well-known/openid-configuration` and `/oauth/token`; `/oauth/authorize` is a page.
- **The consent** (`consent-routes.tsx`, a page on `SITE_URL`; a 404 with OAuth off and on the public MCP host; in full: `reference.md`): `GET /oauth/authorize` proves the request (the client's document fetched fresh, the exact redirect URI, then the rest) and **never redirects** (a refusal is a 400 page, after proof with a "Return to <host>" link, decisions 2026-11-28); the page's headline is the redirect host, read-only the default. The proven request rides signed in one hidden field (`consent-token.ts`, 10 minutes). `POST /oauth/authorize` is `sessionless`: Allow checks email and password on the sign-in's budgets and writes a fingerprint-stamped, hashed, 2-minute code (`grantConsent`, `codes.ts`), then the 303 with `code`, `state`, `iss`; Deny is a 303 `access_denied`.
- **Every answer of both** is `no-store` and `Referrer-Policy: same-origin` (`no-referrer` would null the POST's Origin); both are `secretPath`. The consent page's CSP widens `form-action` to the redirect's origin (`allowFormTarget`, `csp.ts`). The worker never handles `/oauth/*` (`bypassesWorker`). Nightly, `oauth-code-prune.ts` deletes codes a day past expiry. Never logged: the code, state, challenge, verifier, password, a token, the field, a token request's body or the client's name.
- **`POST /oauth/token`** (`token-routes.ts`, `oauth` surface, `public`, `secretPath`, 8 KB): every answer `no-store` and `Pragma: no-cache`; RFC 6749 errors. Checks in order: a form body (the media type in any case, parameters ignored; JSON is `invalid_request`), the schema (each parameter once, `URL_MAX`, no control character: a `%00` would be Postgres's 500), no client authentication (`Authorization` or `client_secret`: `invalid_client` 401), the grant type, then the grant's (`grants.ts`). A refusal charges `OAUTH_TOKEN_LIMIT` (per address, refusals only); past it, a stranger's is the 429, a known grant's stays `invalid_grant`. `scope` is ignored; the answer states the grant's.
- **A grant is a `personal_access_token` of kind `mcp`** with `oauth_client_id`, `access_expires_at` (1 h, the app's clock) and `refresh_token_hash` (`personal_access_token_oauth_check`: all three or none), so everything downstream of `authenticateToken` is an agent token's. Its audience is its kind: a second resource would need an audience column.
- **The code grant** (`exchangeCode`) locks the code's account, then claims the code (unused, unexpired: Postgres's clock), and commits that claim whatever refuses after, so **a code is one attempt**; then client, redirect, resource and PKCE S256 against the row, then `mintToken` in the same transaction (the user's lock, the fingerprint stamp rechecked, the cap without this client's grant or an idle one, and only then that grant revoked: a refused reconnect keeps it). A used code presented again revokes its grant (replay, warn line); a concurrent second use waits on the account and does the same. **The user row before the code row**, as the account deletion's cascade takes them: the other order deadlocked.
- **The refresh grant** (`refreshGrant`) rotates in one statement keyed by the live hash: new access and refresh tokens, a new hour, the use stamped, the old hash into `oauth_retired_refresh_token`, only for a grant in force, of this `client_id` (required), not idle (`oauthGrantNotIdleSql`, the cutoff `idleExpired` uses: 90 days). Nothing rotated is judged by a second statement on a fresh snapshot: **any retired generation is reuse and revokes the grant**, two racing refreshes included (no grace period, decisions 2026-11-28); revoked, idle, another client's or unknown is `invalid_grant`.
- **At /mcp** an expired access token is refusal `expired` (never charged to `BEARER_REFUSAL_LIMIT`: a healthy client's hourly cue; one info line per address per that limit's window, the rest counted into `RefusalSummaries`' line), and every presented-and-refused token's 401 says `error="invalid_token"` (RFC 6750 3.1). Sign out everywhere ends no grant; a new password ends them all. Nightly, `oauth_refresh_prune` drops revoked grants' families.
- **A client document's `logo_uri`, `client_uri`, `tos_uri` and `policy_uri` are never fetched or rendered**: one outbound fetch per consent, and no stranger's image or link on the page.

## Gotchas

- **The e2e server runs OAuth on** wherever SITE_URL is https (`playwright.config.ts` sets `MCP_PUBLIC_URL`), the client's document from `test/support/oauth-client-stub.ts`: `test/oauth-consent.spec.ts` proves Allow's native post reaches the redirect.

- **Production stays off until #1293** sets `MCP_PUBLIC_URL` in the compose, with the gate forwarding the documents and `POST /oauth/token`; set earlier, a connecting client reaches the documents but not the token endpoint.
- **The gate forwards only `POST /mcp` today**: the documents reach the internet only once homelab's `closet-mcp-gate` forwards their exact paths (#1293).
