# OAuth for /mcp: reference

The consent's detail, moved from `AGENTS.md` (#1291) so the auto-loaded doc stays under its cap. Not auto-loaded. Where it disagrees with the code or a spec, they win.

- **The consent** (`consent-routes.tsx`, a page on `SITE_URL`; a 404 with OAuth off and on the public MCP host). `GET /oauth/authorize` (`OAUTH_AUTHORIZE_LIMIT`, no HEAD twin: each one fetches) proves the request in order (`authorize-request.ts`): `clientIdUrl` (https, a path, no raw `?#@\`, written as the parser writes it, no address literal or local name), the Client ID Metadata Document fetched fresh as `untrustedJson` (`client-metadata.ts`: its `client_id` the URL exactly, a public client, 1-5 https or loopback `redirect_uris`), then `redirect_uri` an exact listed string (a loopback entry on any port, RFC 8252), all capped at `URL_MAX`. Until then a refusal is the 400 page with no link; after, the rest (`response_type`, S256, `resource`, scope; a repeat is `invalid_request`, a repeated `resource` `invalid_target`) is a 400 page with a "Return to <host>" link carrying `error`, `state` and `iss`, **never a redirect of ours** (decisions 2026-11-28). The page puts the redirect host as the headline and the client's name only as what it "calls itself" (`displayText`: bidi, zero-width and control characters out, NFKC, 60 characters), warns on a document host other than the redirect's and on loopback, and defaults to read-only (writes offered only when asked).
- **The signed field** (`consent-token.ts`): the proven request as an HS256 JWT on `ACCESS_TOKEN_SECRET`, audience `oauth-consent`, issuer `SITE_URL`, 10 minutes; the POST trusts it alone and never refetches. `CONSENT_FIELD_MAX` is derived from the claim caps, so a request the GET took always fits the POST's schema.
- **`POST /oauth/authorize`** is `sessionless` (no cookie read or set) and budgeted by its body: Allow on the sign-in's (`enforceSignInLimits`, one checker with the login), Deny, which checks nothing and names no email, per address on the GET's `OAUTH_AUTHORIZE_LIMIT` only (on the account budget every Deny would share one bucket). Deny is a 303 `access_denied`; Allow runs `checkSignIn` (one bcrypt for an unknown email too) and `grantConsent` (`codes.ts`): one statement that writes the code only if the password is still the one verified and Agent Access has room, not counting this user's grant from the same client (`personal_access_token.oauth_client_id`), stamped with the fingerprint, 2 minutes, hashed; then the 303 with `code`, `state`, `iss`, built with `URLSearchParams` onto any query the URI has. `logOp` `oauth.consent.granted` names the code row, the hosts and the scope.
