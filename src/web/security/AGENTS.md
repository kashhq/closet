# Request security

_Reference, not auto-loaded:_ [`reference.md`](reference.md) holds the full detail and stories behind Host allowlist, CSRF, Rate limits, The bearer gate, Outbound fetches (SSRF), Logout, Session revocation, Signing in over a live session and The header reaches a document; the rules are below.

- **Host allowlist** (#702; `createAllowedHostHook`, `allowed-host.ts`, root onRequest, just before the same-origin hook, which trusts the Host a rebound page controls): a `request.host` that is not `SITE_URL`'s, an `ALLOWED_HOSTS` entry or loopback (any port), or is missing, is a 421 with one plain-text line naming `ALLOWED_HOSTS` and `SITE_URL` (never the host asked for) on every surface, static paths too; not an `HttpError` (the handler writes a problem or a page). Behind Caddy the original Host arrives, so every name a proxy or scraper uses is an entry; the boot logs `Allowed hosts: ...` and, in production with only loopback allowed, a warning.
- **CSRF** (`createSameOriginHook`, `same-origin.ts`, root onRequest, before the body): a POST, PUT, PATCH or DELETE whose `Origin` (else `Referer`) is neither `requestOrigin` nor `SITE_URL`'s, or is missing, is a 403. Nothing changes state on a GET; the cookie stays `SameSite=Lax`. The bearer surfaces (`surfaceOf`: `/mcp`, `/api`) and `oauth` (OAuth's documents and token endpoint, `assignSurface` holds it to their paths) pass a missing Origin and 403 a foreign one. The only page exemption is `config: { stateless: true }`, allowed only on `STATELESS_ROUTES` (the boot refuses any other); such a route writes nothing, reads under a size cap and answers a redirect. **A `STATELESS_ROUTES` entry is a CSRF exemption: review it as one.** The service worker never relays a navigation POST (#542).
- **Rate limits** are opt-in per route (`global: false`); a budget two doors share is ONE checker (`SIGN_IN_LIMIT` + `SIGN_IN_ACCOUNT_LIMIT` for login and the API sign-in, `LINK_IMPORT_LIMIT`, `weatherLimits`, `PHOTO_UPLOAD_LIMIT`), never one per door. `ACCOUNT_LIMIT` is every route that checks the current password; `API_LIMIT`, `API_PHOTO_LIMIT` (`apiPhotoBytes`), `MCP_LIMIT`, `HEALTH_LIMIT`, `OAUTH_DISCOVERY_LIMIT`, `PUSH_TEST_LIMIT`, `VITALS_LIMIT`, `CLIENT_ERROR_LIMIT` the rest. Every route reading an upload says `config: { photoUpload: true }` (counted before any part is read); a multipart body elsewhere is a 415. Every sign-in attempt counts, so a guesser holds an account shut only while guessing; `MCP_LIMIT` counts tool calls (a batch is refused). Counters live in process memory, one per route config or `createRateLimit` call; a refusal is the 429 page.
- **The bearer gate** (`createBearerGate`, one onRequest hook for `/mcp` and `/api`, before the body): only refusals are charged to `BEARER_REFUSAL_LIMIT`, never a token that opens; a revoked token stays the 401 past the budget.
- **Logout** is `POST /auth/logout` only (a 303 to the login page), through `endSession` (cookie cleared, `Clear-Site-Data: "cache"`), from the one `PostForm` in Profile › Sign out; the worker never relays it. `GET /auth/logout` signs nobody out (a signed-in visitor gets a one-button page).
- **Session revocation**: a token carries `pwf` (the hash's fingerprint) and `sv` (`session_version`), compared on every request in the session's one statement. A new password (`updatePasswordHash`, the one writer, one transaction behind the user's row lock) ends every other session, personal access token and push subscription but this device's; Sign out everywhere bumps `sv` and revokes device tokens and other subscriptions, not agent tokens or invites. A revoked cookie is cleared with `endSession` on whatever route it arrives. Use `"cache"`, never `"storage"` (it would unregister the worker). Signing in over another account (`startSession`) clears the cache too.
- **Trusted proxies**: `request.ip`, `request.protocol` and `request.host` read `X-Forwarded-*` only from peers in `TRUSTED_PROXIES` (Fastify `trustProxy`). Behind Caddy it **must** include Caddy's address, or every visitor is Caddy's IP to the rate limiter and the same-origin check falls back to `SITE_URL`. A peer outside the list sending `X-Forwarded-For` is one warning per boot and `/health/ready`'s optional `trusted_proxies` check down, never a refusal (`UntrustedProxyWatch`, #671).
- **`/mcp` is public** through the `closet-mcp-gate` (`POST /mcp` only), whose address must stay inside `TRUSTED_PROXIES` so `MCP_LIMIT` sees the real client.
- **Refusals do not reveal ids**: what the requester cannot see does not exist for them, a 404 like an unknown id (an unshared wardrobe, a garment outside the addressed wardrobe, anyone else's outfit or entry, someone else's share); what they can see but may not change is a 403 (a VIEW grantee writing). `WardrobeAccess` (`src/web/sharing/access.ts`) documents it; `test/integration/authorization-*.spec.ts` is the matrix. A route whose body or querystring carries a `RowId` (`RESOURCE_ID` symbol, `src/web/schemas.ts`) needs a matrix case like a path-id route, so a request's resource id is always a `RowId`, never a bare `Type.Integer()` (#704).
- **Public pages never show an email**: the share page (`/share`) and its Open Graph and Twitter tags say "Shared by" the owner's first name when set (`sharedBy`, `src/web/share/share-page.tsx`), else nothing; its query reads no email.
- **Redirect targets**: a user-supplied "go back here" value (`?returnTo=`) goes through `safeReturnTo` (`src/web/security/return-to.ts`): same-site paths only, anything else becomes the route's default. Never render or redirect to such a value without it. Sign-in's returnTo adds page targets on top (`signInReturnTo`, `src/web/auth/return-to.ts`; Auth).
- **Timing**: a function that checks a secret a request carries calls `markSecretChecked()`, and that request answers without `Server-Timing` (see Metrics).
- **Secrets in logs**: a route whose path carries a secret (the invite token) sets `config: { secretPath: true }`; every log line names requests through `loggableUrl()`, which then logs the route pattern, and otherwise filters credential shapes from the URL (`scrubSecrets`: a token a client put in a query string). Invite links are built on `requestOrigin`, never the raw Host, and reach script only as a data attribute.
- **A queued write's account** (#178a): a replay names the account that queued it (`X-Closet-Queued`); a root preHandler (`app.ts`) refuses one for another account than the session's, 409 `account`, before the handler writes (`src/web/offline-writes.ts`). Replays are same-origin fetches, so CSRF and the session gate apply unchanged (the gate answers one without a session the 401 by its header, never the navigation's 302); `Idempotency-Key` is logged sanitised and cut to 8 characters.
- **The CSP** (`csp.ts`, #672, decisions 2026-11-25): no `'unsafe-inline'` script; the importmap is the one inline script, by its `sha256`, never a nonce (pages must stay byte-stable); one string feeds the header and the pages (`ViewContext.importMap`); htmx runs no script from a swap. `delivery.spec.ts` recomputes the hash from the served page.
- **Private photo caching**: every photo a user owns is `Cache-Control: private` (`PRIVATE_IMMUTABLE_YEAR`: selfies, every `/file/**` variant): a share can end. Only the watermarked share preview (`/file/watermark/:id`, five minutes) is `public`, for link-preview crawlers (#669).

## Gotchas

- **All user-supplied URL fetches go through `outbound-fetch`.** Never `fetch()`, `http.get` or an HTTP library on a URL a user typed, pasted, shared or that a fetched page named: the production host reaches the NAS, pgvault and the router, and checking a name then making a normal request is open to DNS rebinding. `createOutboundFetcher` checks every resolved address (`isPublicAddress`) and dials the checked one (`outbound-dial.ts`, the one place a socket opens); every redirect (at most 3) is checked the same way; a body is read only for an accepted type under its cap (images never SVG or HEIC). A fixed third-party API names its `hosts`; a credential or JSON body is accepted only with `hosts` and follows no redirect. Log hosts only; the link import never names a host or address to the user. Its `destinations`, `resolve` and `tls` (the TLS fixture's trusted certificate, `test/support/tls-certificate.ts`) options are for specs only (`OutboundStandIn`); never `NODE_TLS_REJECT_UNAUTHORIZED`. The spec stands in for the internet with the loopback alias `127.0.0.2`, which Linux routes and macOS does not without `sudo ifconfig lo0 alias 127.0.0.2`.
- **What every request pays before its handler**: the timing context and the same-origin check at onRequest, the rate limiter only on opted-in routes (`global: false`), then at preValidation, off the static paths and the bearer surfaces, one HS256 verify and **one statement**, the session's user row by primary key: its id, email and the hash's fingerprint cut in SQL, not the hash (a `checksPassword` route's hash and an `?ownerId=` share ride in it: Auth, Sharing); `requireSession` and the views read `req.auth`, never the row again. A static path runs no statement. **Never cache the session's row in the process**: comparing its hash's fingerprint on every request _is_ the revocation, so a cache would keep a revoked cookie working.
- **The request log never holds a credential and skips static paths.** One line per request from the root onResponse hook (logger `Http`): method, `loggableUrl`, status, time, never headers (the cookie is a year-long credential; the logger redacts `cookie`, `authorization`, `set-cookie` too). Fastify's own request logging stays off: it would log every thumbnail and heartbeat.
