# Link import: reference

Moved out of `AGENTS.md` (#723) so the auto-loaded doc keeps only invariants, gotchas and ownership. Not auto-loaded: read it before changing this area. Where it disagrees with the code or a spec, they win.

- **Link import** (continued)
  - **The flow**: "Add from a link" on the new garment form (or Android's share sheet, by way of the service worker's redirect) opens the link page; it fetches nothing until Fetch (a GET never writes). `importLink` (`import.ts`) fetches with `accept: ['html', 'image']`: an image is stored as the **pending photo**; a page goes through `extractProduct`, then up to `MAX_PHOTO_CHOICES` (6) of its image candidates go through `previewChoices`, each turned into a small WebP preview in memory (`Photos.preview`), and the first readable one (in the page's order) stored as the pending photo. `importedForm` (`prefill.ts`, pure) makes the form values: the category's presets fill what the page did not say (as `withPresets`), a stated weight shows in gsm, the price only when in dollars or without a currency (else a notice names it), the product link is the link as given. The answer is the ordinary new-garment form (posting to `POST /wardrobe`) with notices, the pending photo (hidden `linkPhoto` plus its thumb) and, for two or more readable candidates, the choices as buttons with `data:` previews. A tap posts `url` and the current `linkPhoto` (`hx-params`) to the photo route, which stores the pick and discards the photo it replaces; the taps share one queue on the choice group (see Gotchas). The link field is `type="text"` with `inputmode="url"`: a share's "Title https://…" is valid input, and `type="url"` had the browser refuse it before the post. `extractProduct` also says its `confidence` (`product`, `page`, `title-only`; a link redirected up its own path to the shop's home is `title-only`, `leftProductPath`): `title-only` prefills only the link, warns (`TITLE_ONLY`, or `NOTHING_FOUND` for an empty page) and fetches no photo; the MCP tools and the API answer carry it (#675, `docs/decisions.md` 2026-11-14). A page with nothing extractable opens the form with the link kept and a message. A page past 2 MB is read up to it (the fetcher cuts it), so a giant page with its JSON-LD first still imports; a shop that refuses automated fetches is `blocked-by-site` (`linkImport.BLOCKED_BY_SITE`; the MCP tools' errors lead with the reason, so the agent takes another retailer), never a retry: #347 found Shopify product pages 429 HTTP/1.1 clients and serve HTTP/2, which the fetcher now speaks (#496b), with the same honest User-Agent; a 429 over h2, Cloudflare's and AWS WAF's challenges stay refused (`docs/decisions.md` 2026-11-12, 2026-11-13 #496b). `link-import.spec.ts` serves fixture pages from 127.0.0.2 (`test/integration/link-sites.ts`).
- **Link import** (continued)
  - **Memory** (#120): `previewChoices` works on `CHOICE_CONCURRENCY` (2) candidates at a time and keeps only the first readable one's bytes past its preview, so an import holds at most three fetched images of up to 15 MB and two decodes, whatever the page names. Before decoding, each candidate's pixels are read from its header (`Photos.inputPixels`) and taken from `CHOICE_PIXEL_BUDGET`, which is `MAX_INPUT_PIXELS` (one upload's worth, 64 MP) for all the choices together; one past what is left is skipped with a warning, never failing the import. Storing the pick decodes it once more afterwards. Six near-limit photos used to be decoded at once (~1.5 GB of pixels). `LINK_IMPORT_LIMIT` bounds one user's rate; concurrent users multiply it.
  - **Saved at once, without the form** (`save.ts`, `saveGarmentFromLink`): MCP's `add_garment_from_link` and `suggest_garment`, and the API's link import (#192c). `importLink`, `importedForm`, the caller's overrides (a new category or type brings its presets), `readGarmentForm`, then the claim (`createGarmentWithPendingPhoto`); the first readable photo, no choice. A refused form discards the pending photo and is returned for the caller to word (MCP a 400 naming form fields, the API `body/<pointer>` errors); a refused fetch is a 400 or 422 leading with its reason (the page's 502 would be a detail-free 5xx on the API). A new surface that saves from a link calls it, never re-composes the steps.
  - **The order mail reads through it** (#25, `../order-mail.md`): the poll reads each link of a forwarded order email with `readProductPage` (`import.ts`: fetch as HTML, `extractProduct`, nothing stored), and the review list's "Add to closet" runs `importLink` on the kept link. `html.ts` also collects `<a href>` values (`links`, at most `MAX_LINKS`) for it; the poll passes `readProductPage` its `mayFollow`, `importLink` none.
