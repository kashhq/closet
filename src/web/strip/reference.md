# Snap strip: reference

Moved out of `AGENTS.md` (#723) so the auto-loaded doc keeps only invariants, gotchas and ownership. Not auto-loaded: read it before changing this area. Where it disagrees with the code or a spec, they win.

- **The observer**: an IntersectionObserver per strip, rooted on it with `rootMargin: 0px -50% 0px -50%` (a zero-width line down the middle), writes the crossing item's `data-snap-value` into the strip's input and moves `data-selected` / `aria-selected`. It centres the `data-selected` item once when it first watches a strip. **With a mouse (#311)**: the frame also holds two `data-snap-step` buttons (previous/next, `aria-label`s `strip.PREVIOUS`/`NEXT`) after the input, shown only by the `fine` variant (`@media (hover: hover) and (pointer: fine)`, `main.css`): one markup, no UA sniffing. They and the ArrowLeft/ArrowRight keys (a document `keydown` when focus is in a strip, not in a field) centre the item beside the chosen one, so the choice moves through the observer and `snap-strip:choose` like a swipe. Steps count from `heading` (the item a step's smooth scroll is going to, until `scrollend`), else the chosen item: `position()` is the one place both the steps and the buttons read. A keyboard step from a focused item moves focus to its target **at keydown**, never later (#469): Enter or a held key's repeat acts on where the strip is going, and nothing pulls focus back from where the user went meanwhile; Enter on a target still in flight only centres it. The buttons render disabled and `syncSteps` enables each that has a non-inert item to go to (an end or a locked Styling row's neighbour stays disabled; styling.js re-syncs on a lock). Disabled is `aria-disabled` + `aria-disabled:btn-disabled`, never the attribute: a disabled button drops its focus to `<body>` (a key held on Next did at the end). Copy never names the gesture ("swipe"). Proven in `test/styling.spec.ts` (keys dispatched in one task, so the scroll is in flight) and `test/integration/styling.spec.ts` (rendered disabled). **No touch or wheel handlers** (`test/styling.spec.ts` checks the app has none). A capture-phase document click centres a tapped neighbour (an item may be a boosted link whose htmx handler would otherwise navigate first); the chosen item's tap reaches the item.
