# Agent requests

`src/wardrobe/agent-requests.ts` (the machine, pure) and `src/web/requests/` (#681 B1; design `docs/plans/2026-11-27-mcp-oauth.md` sections 3.1, 3.2, 3.7). "Ask your agent": a household member asks on the phone, and the next of **their own** agent tokens to connect over MCP claims and answers it. The pages, the sheet, the outbox kind and Today's card are #1286; the MCP tools #1287; the push on answer #1288.

- **The asker's alone**: `agent_request.owner_id` is the asker; every read and move is `actor.userId`'s, so anyone else's id (a grantee of either permission included) is `NotFound('agentRequest')` on every surface, nothing written (`authorization-account.spec.ts`). No `?ownerId=`. An agent token acts as its user: only the asker's tokens claim or answer.
- **One writer, `transitionRequest`** (`request-actions.ts`) over a typed `RequestTransition` (`ask`, `claim`, `answer`, `withdraw`, `seen`). The ask is one insert with the owner lock folded in (`insertRequest`); every move is `ownerTransaction`, the row `FOR UPDATE` with its lease judged by the transaction's `now()` (`lockRequestState`), `requestMove` (pure, exhaustive), then one UPDATE guarded by the judged status (`writeMove`; a guard that fails throws: a writer skipped the lock). Never write the table elsewhere: the sync triggers refuse a write without the asker's lock.
- **The machine** (`agent-requests.ts`'s header has the table): a claim is held for `CLAIM_LEASE_MINUTES` (30); an expired claim, or one whose token is gone, is free (no timer); a takeover stamps the new token (`claim: 'takeover'` on the op line). claim of a live claim of another token is 409 "Another agent is working on this request"; answer of one is "Another agent took this request"; after a withdrawal "The owner withdrew this request"; twice "Already answered"; Got it before an answer "Not answered yet". withdraw and seen twice are `changed: false`, never an error. Strings: `refusal.agentRequest.*`.
- **Subjects**: at most one (`agent_request_one_subject_check`): a garment the asker sees (own or shared), their own trip or need. Checked at the ask inside the insert's statement (an unseen one is its kind's 404) and again on every read (`readRequests` joins the garment only while seen: a share ended or a garment deleted reads as no subject). **`garment_id` is a soft reference, no foreign key** (decisions 2026-11-27): a grantor's garment delete would otherwise set null on the grantee's synced row without the grantee's lock, which the sync triggers refuse (the grantor's delete would fail). Trip and need are the asker's own, `ON DELETE SET NULL`.
- **Idempotent ask**: a `clientId` (the API's retry, #1286's outbox) is stored; the `(owner_id, client_id)` constraint arbitrates; a replay answers the first request (200) with its status now, even once its subject is no longer seen (the id names the ask).
- **The feed is a replica, the resource reads fresh** (#1310): the feed carries `agentRequest` as stored (`SyncedAgentRequest`: its subject's stored id, the garment's included, no agent names, since a token's rename moves no request's revision). Ending, restarting or accepting a share moves no request's revision, so a live judgment in the feed would never be resent; the client resolves the reference against the garments it holds, and a share's end arrives as `revokedWardrobes` (src/web/sync/AGENTS.md), as for every cross-wardrobe reference. The API resource and list (a fresh read per request) judge the subject live (`subjectSql`, `readRequests`). Joining `SYNC_ROOTS` moved `FEED_COVERAGE`: every device's next sync is one full re-sync.
- **API** (`api-routes.ts`, `request-resource.ts`): `GET /agent-requests` (newest first, id keyset), `POST /agent-requests` (201 + `Location`; the body stored as `storedText`, CRLF to LF and trimmed, then 1..500 in `checkedText`, the one length check of every surface; the route schemas bound only what is sent, `REQUEST_BODY_SENT_MAX`, since a form's CRLF counts twice), `GET /agent-requests/{id}` (`claimedBy` only while claimed, `answeredBy`), `POST .../withdraw`, `POST .../seen` (each `{ id, status, changed }`). Operation ids in `operations.ts`, the page routes' twins in `PAGE_WRITES`; the agent's `claim_agent_request` and `answer_agent_request` are `MCP_WRITES` agentOnly lines (#1287).
- **Pages** (#1286, `routes.tsx`, each the API route's twin in `PAGE_WRITES`): `POST /requests` (the ask: 303 to `/requests/:id`; a replay 204 `answerReplay`; a subject is `subjectKind` + `subjectId`, both or neither, a schema `dependencies`), `GET /requests` (newest first, `?before=` keyset, lenient), `GET /requests/:id` (body, subject linked through `subjectView`, status, the answer with its `AgentBadge`, Withdraw or Got it), `POST /requests/:id/withdraw` (asks first, `confirm`), `POST /requests/:id/seen` (`returnTo`, Today's card). Profile has a row to the list (not a `SETTINGS_ROWS` setting).
- **The sheet is `AskAgent`** (`ask-sheet.tsx`): an opener, its "Waiting to sync" and a `form` `Sheet` holding a `PostForm` with `offlineQueue="request"`, on Today (no subject), a need's card (owner only), a trip's page and a garment's page (anyone who sees it). Static markup: it names no agent state, so the Wishlist (a stale-while-revalidate tab root) stays byte-stable; the no-agent line (`agentConnectedSql`, an `mcp` token in force) is on Today's card and the two pages. Offline it queues (outbox kind `request`, key `<region>:<clientId>`, the region `requestTarget(subject)`, the id minted by the page at each tap: `src/web/shell/outbox.md`, decisions 2026-11-28); Withdraw and Got it stay `data-needs-network`.
- **Today's card** (`today-card.tsx`, `todayRequestsSql` in Today's one statement): open, claimed (the token's badge) and answered-not-seen requests, newest first, at most `TODAY_REQUESTS` (3), then "N more"; Got it there returns to Today.
- **Never logged**: the body or the answer. Each change is one `agent.request.<asked|claimed|answered|withdrawn|seen>` line from `transitionRequest` with `requestId`, `from`/`to`, the token on an agent's move and the surface; a refusal is the error handler's line with its `logDetail`.
- **Tests**: `agent-requests.spec.ts` (the API; the pages and Today's card; two claimants raced on the owner lock with `interleave`; a lease taken over; an answer after a withdrawal), `src/wardrobe/agent-requests.spec.ts` (every edge), `api-changes.spec.ts` (the feed), `authorization-account.routes.ts` (the matrix rows: the pages and their API twins, another's request a 404 everywhere; a grantee may ask about a shared garment), `queued-writes.spec.ts` (an ask replayed once, the sheet's markup), `test/ask-agent.spec.ts` (offline at 390 px, then Today).
