## Gotchas

- **Scratch databases are created `template template0` with `C` collation and ctype**, whatever the server's default: the ordering assertions ("Teal" before "mauve") were validated on the production host's pgvault-dev (C), while CI's postgres image and a Mac's pgvault-dev are `en_US.utf8`. A spec's database is a clone of `closet_tpl_<hash of drizzle/>` (made once per run by the globalSetup, kept on the server until drizzle/ changes; the sweep drops the others), so the boot applies nothing; a spec that needs an older shape (`migration-runner.spec.ts`) asks `createScratchDatabase` for an empty one (`beforeBoot` in the harness does).
- **The integration tier's harness, scratch databases and authorization matrix** have their own gotchas: `docs/testing-integration.md` (how createTestApp configures and signs in, how scratch databases are dated and swept, how the matrix and its coverage check work). Read it before changing `test/integration/harness.ts`, `test/support/scratch-database.ts` or an `authorization-*.spec.ts`.
- **Statement counts are pinned in the specs, the one owner** (#721): the ratchet's `build/statements.json` only reports them. An API route that is a page route's twin is a `TwinCase` in `api-statements.spec.ts` (`twin-statements.ts`): its operation comes from `PAGE_WRITES`, its URL and success status from the registered route, and it pays its twin's count plus `extra`, the why beside it.
- **Sequence a race on a lock with `test/integration/interleave.ts`, never a sleep or a short poll** (#621): `interleave(db, first, second)` holds the first writer's transaction until the second blocks, and a hand-built holder (a `pg` client, `holdOpen`) takes its `backendPid` and waits with `waitForBlockedOn(db, pid, count)`. It looks for a backend in `pg_blocking_pids` behind that holder, so a bcrypt hash, a third writer's lock or another spec's wait never satisfies it, and it has no deadline but the test's timeout. Never `expect.poll` on `pg_stat_activity` (its 1 s default flaked under load) and never a count of `wait_event_type = 'Lock'` backends; `interleave.spec.ts` proves the distinction.
- **Playwright serves whatever is on :3000** (or on `PORT`, which `playwright.config.ts`'s `baseURL`, the spec's `APP_ORIGIN` and the started server all follow: `PORT=3107` runs a worktree's specs beside another's). Its webServer is `npm run start:test` (`test/support/test-server.ts`): the existing build (the npm scripts build first; it imports `dist/`, so a stale or missing build is what runs) served by `serve()` with a stub cutout runner (`cutout-stub.ts`), so an upload goes pending and its cutout arrives without the model. `reuseExistingServer` is on outside CI, so a running `start:dev`/`start:prod` is tested instead, with the real model on uploads. Stop it before `verify:push`.
- **The stub cutout answers at once; a spec that shows a cutout pending holds it** (`cutouts.hold(email)`, `cutout-hold.ts`, #230), and a spec that needs the cutout waits for the page's `?v=2`: `docs/testing-cutouts.md`.
- **A client module's browser behaviour goes in a `.browser.spec.ts` beside it** (`views/assets/page/mask-editor.browser.spec.ts`, #1225; the bundling and mounting shared by the specs is `test/support/page-module-browser.ts`, never a file under `page/`, which the page build would take): the `audit-browser` vitest project (`npm run test:audit-browser`, run first by `make ci-e2e`) bundles the module from source into a real Chromium page of fixed markup with `page.route` for its requests; it is not a Playwright scenario, but it runs inside `make ci-e2e`, so its time counts against the tier's 180 s budget.
- **The Safari projects (`webkit`, `Mobile Safari`) run nightly, not on PRs** (#179). A spec Playwright's WebKit cannot run skips with a reason from `webkit-limits.ts`, never on `browserName !== 'chromium'` (but for a CDP session, `CDP_IS_CHROMIUM_ONLY`: Firefox has none either); page errors go through `pageErrors(page)`, which drops a WebKit line that is no error. A spec that fakes `/health/live` with `page.route` runs with `serviceWorkers: 'block'` (WebKit sends a controlled page's fetches past the route, #436). Running WebKit on the production host and reading a failure: `docs/testing-webkit.md`.
- **Playwright runs its scenarios in parallel** (`playwright.config.ts`) against one server and database, so a spec owns its data: its own users. `screenshots.spec.ts` is not a test but the 390 px persona screenshots (`make screenshots`, `SEED_SCREENSHOTS`; serial, personas reset at the start of every attempt, src/seed/AGENTS.md); the gate's e2e tier ignores it.
- **Vitest runs a function returned from `beforeEach`/`beforeAll` as that hook's cleanup.** `beforeEach(() => mock.mockReset())` returns the mock, so Vitest calls it after every test; with `mockRejectedValue` set, the test fails with the mock's rejection. Brace hook bodies that return anything. Jest ignored the return value.
- **`vi.mock` factories return the module namespace.** Mocking a CommonJS default export is `vi.mock('heic-decode', () => ({ default: { all: vi.fn() } }))`, and `vi.mocked(heicDecode.all)` types it; Jest's `() => jest.fn()` shape throws ("is not returning an object"). `vi.mock` is hoisted like `jest.mock`.
- **Vitest does not type-check.** It compiles with Vite's Oxc transform, which strips types; `npm run typecheck` (the root `tsconfig.json`: `src/`, `test/`, `scripts/`, the configs; no test globals, so a helper that calls `expect` without importing it fails here) and `npm run build` (`tsc -p tsconfig.build.json`, `src/` only) do. The service worker has its own `views/assets/tsconfig.json` (WebWorker lib, strict) because it runs in a worker scope. It was 790 errors until 2026-09-25, one of them a live 500 (a misspelled MikroORM exception import is `undefined` at runtime, so `instanceof` threw).
- **`locator.click()` can move a scroll-snap strip.** Its actionability scroll-into-view (retried with other alignments when the page is slow) scrolls Styling's strip, which snaps onto a neighbour: the tap lands on one garment while the row chooses another (1 in 3 runs under CPU load, #105). To tap a strip item as a finger does, wait until it sits centred and `page.mouse.click` its middle (`tap`, `test/styling.spec.ts`). Wait on events, never frames: `settled` resolves when the chosen item is centred or at the strip's `scrollend` (a frame-counting wait was #486's suspect); to act while a strip's scroll is in flight, dispatch the events in one `evaluate` task (`keysInFlight`), never a sleep.
- **A page-audit step on a rate-limited route or tool declares `limits`** (`LIMIT` in `scripts/audit/steps.ts`, from the app's constant); the walk paces each budget (`budget.ts`). Never size `runs` to dodge a limit (#374; `docs/perf/README.md`, Rate limits).
- **Accessibility is the page audit's, not a Playwright scenario** (#722): `audit:pages` opens every plain-GET page step in Chromium at 390 px and counts axe violations, fields under 16 px and targets under 44 px per page; the nightly's `--compare` fails on a violation kind (page, rule, element pattern) absent from `docs/perf/baseline.json` and only warns (WORSE) when a node count rises, since counts follow the seed's dates and the platform (`docs/perf/README.md`, Accessibility).
- **Moved rules** (detail in `reference.md`): a spec asserting what is cached calls `withoutWarming(context)` first. A fake-clock spec never sees Navigation Timing. No spec uses a persistent context to subscribe to push. Never write a spec only to lift a number, and covered branches must not move with the date (pin the day). The shifted clock moves only JS's `Date`, never a real-clock reader. Playwright's order mail points at `jmap-stub.ts`, never Fastmail. Bump Vitest only when npm 10 resolves it.
